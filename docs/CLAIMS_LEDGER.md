# Claims ledger

Every claim worth making about PathAble, with the exact wording that is supportable, the evidence behind it, and
the overstatement it is one word away from. If a sentence about this project is not in this file, it has not been
checked.

**Measured against** `main` at the commit this document ships on, dataset
`51585450-8ff5-409d-a02e-66d5a3c5e260`, checksum `51e75f7896ab725d29120fe4363c607bea68eed260d830482d6677f827d2e906`.
Every wall-clock figure was produced on one Windows laptop under memory pressure and is a shape, not a service
level.

## Prohibited claims

Not "avoid" — **prohibited**. Each is false today, and several would be harmful.

| Claim                                                                 | Why it is false                                                                                                                     |
| --------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------- |
| Deployed / live / hosted / "try it at…"                               | No hosting account, no URL, no provisioned resource.                                                                                |
| Real users, adoption, traffic, "used by…"                             | Nobody outside this repository has used it.                                                                                         |
| Production latency, throughput, capacity, uptime, SLA                 | Every figure is one laptop. The concurrency probe was six requests per client.                                                      |
| High availability                                                     | Single node everywhere in the proposal; nothing is redundant.                                                                       |
| Accessibility certified / safe / guaranteed passable                  | It advises. Two routing errors are not symmetric, and this is the dangerous one.                                                    |
| Scientifically validated accessibility model                          | The cost weights are engineering judgement, never validated against real mobility-aid users.                                        |
| Machine learning / AI-powered / predictive                            | Gate C is not started. Every response says `ml_predictions_used: false`.                                                            |
| Solved missing accessibility data                                     | It _reports_ the gap. On the demo journey the gap is 100%.                                                                          |
| Coverage beyond Waterloo                                              | One region, one dataset.                                                                                                            |
| Open source                                                           | Source-visible, all rights reserved. See [`LICENSING.md`](../LICENSING.md).                                                         |
| "Fully tested" / "100% coverage"                                      | 89.09% backend in CI, 92.83% frontend statements, with named gaps.                                                                  |
| On-the-ground verified routes                                         | Nobody has walked them.                                                                                                             |
| Overture enriches PathAble's accessibility data                       | Measured in Waterloo: every examined Overture accessibility attribute is on an OSM-built segment. It is OSM's evidence, relabelled. |
| Overture independently confirms OSM accessibility evidence            | The same measurement: there is nothing independent in it to confirm with.                                                           |
| TomTom-sourced Overture segments add accessibility information        | The 325 TomTom-only Waterloo segments carry none of the examined attributes.                                                        |
| PathAble synchronizes with Overture / incremental updates are correct | PA-GEO-01 is read-only. Nothing is synchronized, activated or re-routed.                                                            |
| Rollback-safe synchronized graph updates                              | No synchronization exists, and a retired dataset cannot be reactivated ([KI-10](development/KNOWN_ISSUES.md)).                      |
| Overture replaces OSM, or is more accurate or complete than OSM       | Never measured. OSM remains the routing source.                                                                                     |
| An OSM id match means the same OSM revision                           | Only true where version evidence says so; PathAble stores no versions.                                                              |

## What building this ledger caught

Checking each claim against the file behind it found three the repository was already making and could not
support; a fourth was found later, while reading the dataset for PA-GEO-01. They are corrected in place; they are listed here because a ledger that never catches anything is
decoration.

| Was                                                                                               | Is                                                                       | How it was wrong                                                                                                                                                                                                                                                              |
| ------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| "Median detour was 70 m" (`docs/product/PHASES.md`, since 2026-08-20, and repeated here in draft) | 86.1 m across the 18 journeys that change; 83.8 m across all 19 routable | Never in the corpus. Recomputing from `waterloo-routes.json` at the commit that first published the figure gives 86.05 — so it was wrong when written, not stale.                                                                                                             |
| "89.13% backend coverage", published with no measurement context                                  | 89.09% in CI; 89.13% locally on Windows                                  | Both runs are real — one Windows-only test is skipped on Linux, which moves the branch total. The figure was published without saying which run produced it, so a reader checking it against CI would have found it wrong. Now attributed to CI, with the local figure named. |
| "Eight of its nine full-stack tests skip in CI"                                                   | All nine skip; 9 of the 16 full-stack tests in total                     | The `beforeEach` guard covers every test in the file. CI reports `9 skipped, 7 passed`.                                                                                                                                                                                       |
| "A dataset is immutable once activated" (2.5, since the ledger was written)                       | Activation is atomic; enrichment is not yet immutable                    | Found in PA-GEO-01: the live Waterloo dataset was activated at 00:05:28Z on 2026-08-18 and its elevation sampled at 00:12:04Z, into the same rows, by the same code path the lifecycle claimed could not do that.                                                             |

None of the first three changes an argument; the fourth changes what synchronization can be built on. That is rather the point: figures drift by carelessness, not by
intent, and the only defence is checking each one against the file that produced it.

## Wording that is safe by construction

- "Locally validated production-container build" — not "production deployment".
- "Recorded demo" or "local production-build demo" — never "live demo".
- "Measured on one laptop under memory pressure" — attached to every wall-clock figure.
- "Proposed" — attached to every sentence about hosting.
- "Reports unknown" — never "handles" or "resolves" unknown.
